# Notion Plans DB — Bulk Status Recovery from plan_registration_cache.json

## 1. Context

At ~2026-05-10T10:50 UTC, **all 328 rows in the Notion Plans DB were bulk-overwritten to Status="Not Started"**. User observed: "notion plans were all moved to Not Started — is that the right move?"

It was not. Per `.windsurf/rules/notion-plans-taxonomy.md`, the canonical statuses are `In Progress / Not Started / Deferred / Waiting / Completed / Retired / Archived`, and constitutional §36 makes Plans DB Status authoritative for `wave_execution_state.py start` gating and CI gate `NP4` plan-Notion wave freshness.

**Pre-corruption distribution** (from `.windsurf/state/plan_registration_cache.json`, snapshot 2026-05-10T01:44:17Z):

| Status | Count |
|---|---|
| Completed | 248 |
| Retired | 52 |
| Not Started | 10 |
| Archived | 8 |
| In Progress | 5 |
| Waiting | 2 |
| Deferred | 2 |
| Enhancement (non-canonical) | 1 |
| **Total** | **328** |

**Post-corruption**: all 328 → `Not Started`. Net delta: 318 rows misclassified.

## 2. Recovery Oracle

`.windsurf/state/plan_registration_cache.json` is generated by `.windsurf/scripts/_plan_registration.py` querying Notion. The 2026-05-10T01:44:17Z snapshot is **9h pre-corruption** and reflects authoritative Notion state at that moment. Each entry is keyed by slug and carries:

```json
{
  "<slug>": {
    "status": "<canonical status>",
    "page_id": "<notion uuid>",
    "exists_on_disk": true|false,
    "has_ai_summary": true|false
  }
}
```

This is the source of truth for restoration. We do NOT need to re-derive from on-disk plan markdown.

## 3. Non-Goals

- **NOT** re-deriving Status from on-disk plan markdown (the cache snapshot is more reliable than ad-hoc inference).
- **NOT** fixing the upstream cause of the bulk overwrite — that's a separate RCA plan (`DEFERRED_SCOPE: P2 notion-plans-bulk-write-rca` will be filed at plan completion).
- **NOT** repairing the 1 non-canonical "Enhancement" row — flag for manual review, leave as-is.
- **NOT** patching backlog Items DB (only Plans DB is observed corrupt).
